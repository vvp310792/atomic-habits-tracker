# Атомные привычки — трекер привычек для Android

Нативное Android-приложение (Kotlin + Jetpack Compose) для ежедневного
трекинга привычек, вдохновлённое форматом [Tick It — Habit Tracker](https://play.google.com/store/apps/details?id=habittracker.todolist.tickit.daily.planner)
и книгой Джеймса Клира «Атомные привычки».

## Возможности

1. **Ежедневный трекинг** — лента дат в виде колец прогресса (последние 14
   дней) наверху, а привычки на выбранный день разбиты на три блока —
   Утро / День / Вечер — с отметкой в один тап.
2. **Уведомления** — персональное время напоминания на каждую привычку,
   с быстрой кнопкой «Готово ✓» прямо в уведомлении.
3. **Облачная синхронизация через Firebase** — вход через Google или по
   email/паролю, дальше всё само: привычки и история отметок сохраняются
   в Firestore в реальном времени, никаких кнопок «Экспортировать»/
   «Восстановить» не нужно. Удалили и переустановили приложение —
   войдите под тем же аккаунтом, и всё вернётся.
4. **Графики по каждой привычке** — текущая и лучшая серия (streak), % выполнения,
   календарь-«тепловая карта» и столбчатый график за 30 дней.
5. **Теги по сферам жизни** — 7 фиксированных тегов с закреплёнными цветами
   (Карьера — фиолетовый, Интеллект — синий, Саморазвитие — голубой,
   Финансы — зелёный, Общество — оранжевый, Здоровье — красный,
   Семья — розовый), видны бейджем на карточке каждой привычки.
6. **4 закона Джеймса Клира** — при создании привычки можно сразу заполнить
   все 4 закона атомных привычек:
   1. Сделай очевидной (где и когда)
   2. Сделай привлекательной (habit stacking / temptation bundling)
   3. Сделай лёгкой (правило двух минут)
   4. Сделай приятной (мгновенная награда)
7. **Привычка-стек (habit stacking)** — библиотека уже сложившихся привычек
   (полезных и вредных) как точек привязки; новую привычку можно прикрепить
   к любой из них или к уже трекаемой привычке по формуле Клира «После X
   я делаю Y» — цепочка видна на карточке привычки и растёт сама по мере
   того, как новые привычки становятся устоявшимися.
8. **Обновление прямо из приложения** — кнопка «Проверить обновления» в
   настройках сама находит последнюю сборку в GitHub Releases этого
   репозитория, скачивает и запускает установку — заходить на GitHub вручную
   не нужно.

## ⚠️ Важно: как собрать APK

Этот репозиторий содержит **исходный код**, а не готовый `.apk`-файл — GitHub
не хранит бинарные сборки в исходниках. Собрать реальный `.apk` можно двумя
способами (оба описаны подробно в [`docs/SETUP_ANDROID_STUDIO.md`](docs/SETUP_ANDROID_STUDIO.md)):

- **Автоматически в облаке** — репозиторий уже содержит GitHub Actions
  (`.github/workflows/build.yml`), который сам соберёт debug-APK при каждом
  push и опубликует его как GitHub Release — Android Studio для этого не нужна.
- **Локально в Android Studio** — `Build → Build APK(s)`, обычный процесс.

Но прежде чем APK заработает по-настоящему (вход через Google, синхронизация),
нужно один раз настроить Firebase — см. [`docs/SETUP_FIREBASE.md`](docs/SETUP_FIREBASE.md).

## Структура проекта

```
app/src/main/java/com/atomichabits/tracker/
├── data/            Room-сущности (Habit, HabitLog), DAO, репозиторий (локальный кеш)
├── notifications/   Планировщик напоминаний (AlarmManager), BroadcastReceiver'ы
├── sync/            Firebase Auth (вход через Google) + Firestore (облачная синхронизация)
├── update/          Проверка и установка обновлений из GitHub Releases
├── ui/
│   ├── home/        Главный экран — лента дат + привычки по времени дня
│   ├── addedit/      Создание/редактирование привычки + 4 закона Клира
│   ├── detail/       Статистика, тепловая карта, график
│   ├── settings/     Вход через Google, уведомления, обновления
│   ├── components/   Переиспользуемые UI-компоненты
│   └── theme/        Material 3 тема
firestore.rules         Правила безопасности (доступ только к своим данным)
firestore.indexes.json  Индексы Firestore (пока не требуются)
firebase.json            Конфиг Firebase CLI для деплоя правил
keystore/debug.keystore Фиксированный debug-ключ подписи (нужен для стабильного входа через Google)
docs/
├── SETUP_ANDROID_STUDIO.md   Сборка APK (Android Studio и GitHub Actions)
└── SETUP_FIREBASE.md         Настройка Firebase: проект, вход через Google, секреты (10 минут)
```

## Технологии

- **Kotlin** + **Jetpack Compose** (Material 3) — весь UI
- **Room** — локальный кеш (офлайн-first: экраны всегда читают из Room,
  Firestore синхронизируется в фоне)
- **Firebase Firestore** — облачная база, источник истины при синхронизации
- **Firebase Auth + Credential Manager** — вход через Google или email/пароль,
  им же ограничен доступ к данным в Firestore (см. `firestore.rules`)
- **AlarmManager** — точные ежедневные напоминания, переживающие перезагрузку
- **Compose Canvas** — 30-дневный график и кольца прогресса рисуются напрямую,
  без сторонней библиотеки графиков
- **OkHttp** — только для проверки обновлений через GitHub API
- Минимум **Android 8.0 (API 26)**, целевой **Android 15 (API 35)**

## Быстрый старт

1. Прочитайте [`docs/SETUP_FIREBASE.md`](docs/SETUP_FIREBASE.md) и настройте
   проект Firebase (10 минут, один раз, полностью через браузер).
2. Прочитайте [`docs/SETUP_ANDROID_STUDIO.md`](docs/SETUP_ANDROID_STUDIO.md) и
   соберите `.apk` любым из двух способов.
3. Установите APK на телефон, откройте настройки → «Войти через Google».
4. Создайте первую привычку — заполните 4 закона, если хотите.

## Известные ограничения / что можно улучшить дальше

- Debug-сборка не подписана релизным ключом — этого достаточно для личной
  установки, но не для публикации в Play Store.
- **Первый раз после появления кнопки «Проверить обновления»** её ещё нет в
  уже установленной версии — этот самый APK нужно поставить вручную один
  последний раз. Все версии после этого уже можно ставить прямо из приложения.
- Поддерживается один Google-аккаунт за раз (тот, под которым вошли) —
  этого достаточно для личного трекера, каким и задумывалось приложение.
- Синхронизация логов между несколькими одновременно активными устройствами
  корректно обрабатывает добавление/изменение и удаление отметок, но если
  один и тот же день отредактирован на двух устройствах одновременно и
  офлайн — побеждает последняя запись (Firestore last-write-wins), отдельного
  слияния конфликтов нет.
