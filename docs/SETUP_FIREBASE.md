# Настройка Firebase (облачная база + вход через Google)

Это заменяет прежнюю схему на Google Таблицах. Разница в подходе:

- **Раньше:** сихронизация через самописный Apps Script и длинную ссылку,
  которая по сути работала как пароль. Нужно было вручную обновлять скрипт
  в редакторе Apps Script (который почти не работает на телефоне).
- **Теперь:** привычки и история хранятся в Firestore (облачная база от
  Google), доступ к которой даёт **вход через ваш личный Google-аккаунт**.
  Никакого скрипта нет вообще — приложение общается с базой напрямую.
  Синхронизация — в реальном времени, без кнопок «Экспортировать»/
  «Восстановить»: просто вошли в аккаунт, и всё само на месте.

Настройка делается один раз, полностью через браузер (телефон подходит).

## Шаг 1. Создайте проект Firebase

1. Откройте [console.firebase.google.com](https://console.firebase.google.com)
2. **Add project** → любое имя → Google Analytics можно отключить (не нужен)

## Шаг 2. Зарегистрируйте Android-приложение

1. В проекте нажмите значок **Android** → **Add app**
2. **Package name** строго: `com.atomichabits.tracker`
3. **Debug signing certificate SHA-1** — вставьте:
   ```
   B7:23:41:BA:A7:E3:2D:FD:FF:CF:F9:3A:9C:6A:4D:3C:40:A3:F3:3B
   ```
   Это отпечаток фиксированного debug-ключа, который лежит в репозитории
   (`keystore/debug.keystore`) и используется на каждой сборке в CI — именно
   поэтому отпечаток один и тот же всегда, а вход через Google не сломается
   после следующего push.
4. Скачается `google-services.json` — он понадобится в шаге 5.

## Шаг 3. Включите Firestore

Слева в меню: **Build → Firestore Database → Create database**. Любой
регион. Правила безопасности настраивать вручную не нужно — они уже описаны
в `firestore.rules` в репозитории и деплоятся автоматически (см. шаг 6).

## Шаг 4. Включите вход через Google

**Build → Authentication → Get started → Sign-in method** → включите
провайдер **Google**.

После включения там же (или в **Project settings → General**, в блоке
Web SDK configuration) появится **Web client ID** вида
`123456789-abc...apps.googleusercontent.com` — он понадобится в шаге 5.

## Шаг 5. Добавьте секреты в GitHub

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
Добавьте два секрета:

- **`GOOGLE_SERVICES_JSON`** — откройте скачанный в шаге 2 файл текстовым
  редактором, скопируйте всё содержимое целиком, вставьте как значение
- **`GOOGLE_WEB_CLIENT_ID`** — строка из шага 4

После следующего push эти значения автоматически попадут в собранный APK.

## Шаг 6 (необязательно). Автодеплой правил безопасности

Если поменяете `firestore.rules` в репозитории, изменения нужно применить к
самому проекту Firebase. Можно вручную (Firebase Console → Firestore →
Rules → вставить → Publish), а можно один раз настроить автоматику:

1. Firebase Console → значок шестерёнки → **Project settings → Service accounts**
   → **Generate new private key** → скачается JSON
2. Добавьте в GitHub секреты:
   - **`FIREBASE_SERVICE_ACCOUNT`** — содержимое скачанного JSON целиком
   - **`FIREBASE_PROJECT_ID`** — Project ID (Project settings → General, в самом верху)
3. Готово — джоб **deploy-firestore-rules** в GitHub Actions сам применит
   правила при каждом push, если файл `firestore.rules` изменился.

Если эти два секрета не заданы, джоб просто ничего не делает — сборка APK
на это никак не влияет.

## Как этим пользоваться в приложении

1. Настройки (⚙️) → **«Войти через Google»**
2. Выберите свой аккаунт — дальше всё автоматически: новые привычки и
   отметки сразу же уходят в облако, а на любом другом устройстве/после
   переустановки приложения достаточно **снова войти под тем же аккаунтом** —
   всё подтянется само, без кода/ссылки/файла, который надо помнить.
3. Если хотите прекратить синхронизацию — «Выйти» в тех же настройках
   (локальные данные на устройстве при этом никуда не денутся).

## Диагностика

- **«Не удалось войти»** → чаще всего SHA-1 в Firebase не совпадает с тем,
  что зашито в собранный APK. Проверьте, что использовали именно тот
  отпечаток из шага 2, и что сборка была после того, как вы этот SHA-1
  добавили в Firebase (более ранние APK, собранные до этого, тоже не будут
  работать — соберите заново).
- **Вход проходит, но данные не появляются** → проверьте, что
  `GOOGLE_SERVICES_JSON` в секретах — это именно содержимое файла, а не
  путь к нему, и что JSON не обрезан при копировании.
- **Хочу проверить, что данные реально пишутся** → Firebase Console →
  Firestore Database → Data — там будет видно дерево
  `users/{ваш uid}/habits/...` и `.../logs/...` в реальном времени.
