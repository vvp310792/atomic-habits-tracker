# Настройка Firebase (облачная база + вход через Google или email/пароль)

Это заменяет прежнюю схему на Google Таблицах. Разница в подходе:

- **Раньше:** сихронизация через самописный Apps Script и длинную ссылку,
  которая по сути работала как пароль. Нужно было вручную обновлять скрипт
  в редакторе Apps Script (который почти не работает на телефоне).
- **Теперь:** привычки и история хранятся в Firestore (облачная база от
  Google), доступ к которой даёт **вход в аккаунт** — либо через Google,
  либо по email/паролю. Никакого скрипта нет вообще — приложение общается
  с базой напрямую. Синхронизация — в реальном времени, без кнопок
  «Экспортировать»/«Восстановить»: просто вошли в аккаунт, и всё само на месте.

Используется существующий проект **`atomic-habits-17a37`** — заводить новый
не нужно.

## Шаг 1. Зарегистрируйте Android-приложение в проекте

1. Откройте [console.firebase.google.com](https://console.firebase.google.com)
   → проект **atomic-habits-17a37**
2. Значок **Android** → **Add app**
3. **Package name** строго: `com.atomichabits.tracker`
4. **Debug signing certificate SHA-1** — вставьте:
   ```
   B7:23:41:BA:A7:E3:2D:FD:FF:CF:F9:3A:9C:6A:4D:3C:40:A3:F3:3B
   ```
   Это отпечаток фиксированного debug-ключа, который лежит в репозитории
   (`keystore/debug.keystore`) и используется на каждой сборке в CI — именно
   поэтому отпечаток один и тот же всегда, а вход через Google не сломается
   после следующего push.
5. Скачается `google-services.json` — он понадобится в шаге 4.

## Шаг 2. Включите Firestore

Слева в меню: **Build → Firestore Database → Create database**. Любой
регион. Правила безопасности настраивать вручную не нужно — они уже описаны
в `firestore.rules` в репозитории и деплоятся автоматически (см. шаг 5).

## Шаг 3. Включите способы входа

**Build → Authentication → Get started → Sign-in method** → включите
**оба** провайдера:

- **Email/Password** — просто включить тумблер, больше ничего не требуется
- **Google** — после включения там же (или в **Project settings → General**,
  в блоке Web SDK configuration) появится **Web client ID** вида
  `123456789-abc...apps.googleusercontent.com` — он понадобится в шаге 4

## Шаг 4. Пришлите мне значения

`google-services.json` и Web Client ID (из шага 3) **не секретные** — это
подтверждает сама документация Google: защита данных обеспечивается
правилами Firestore и самим входом, а не скрытностью этих значений. Поэтому
никаких GitHub Secrets заводить не нужно — просто пришлите оба значения мне
в чат, я вставлю их прямо в код и запушу.

## Шаг 5 (необязательно). Автодеплой правил безопасности

Если поменяете `firestore.rules` в репозитории, изменения нужно применить к
самому проекту Firebase. Можно вручную (Firebase Console → Firestore →
Rules → вставить → Publish), а можно один раз настроить автоматику:

1. Firebase Console → значок шестерёнки → **Project settings → Service accounts**
   → **Generate new private key** → скачается JSON
2. Добавьте в GitHub секреты (**Settings → Secrets and variables → Actions →
   New repository secret**) один секрет:
   - **`FIREBASE_SERVICE_ACCOUNT`** — содержимое скачанного JSON целиком
     (это единственное по-настоящему секретное значение здесь — закрытый
     ключ с правами администратора проекта, никогда не коммитьте его в код)
3. Готово — джоб **deploy-firestore-rules** в GitHub Actions сам применит
   правила при каждом push, если файл `firestore.rules` изменился (project ID
   уже прописан в самом workflow, отдельно указывать не нужно).

Если секрет не задан, джоб просто ничего не делает — сборка APK на это
никак не влияет.

## Как этим пользоваться в приложении

1. Настройки (⚙️) → введите email и пароль → **«Войти»** (если аккаунта ещё
   нет — **«Зарегистрироваться»**), либо **«Войти через Google»**
2. Дальше всё автоматически: новые привычки и отметки сразу же уходят в
   облако, а на любом другом устройстве/после переустановки приложения
   достаточно **снова войти под тем же способом** — всё подтянется само,
   без кода/ссылки/файла, который надо помнить.
3. Забыли пароль — кнопка «Забыли пароль?» пришлёт письмо для сброса на
   указанный email.
4. Если хотите прекратить синхронизацию — «Выйти» в тех же настройках
   (локальные данные на устройстве при этом никуда не денутся).

## Диагностика

- **«Не удалось войти» (через Google)** → чаще всего SHA-1 в Firebase не
  совпадает с тем, что зашито в собранный APK. Проверьте, что использовали
  именно тот отпечаток из шага 1, и что сборка была после того, как вы этот
  SHA-1 добавили в Firebase (более ранние APK, собранные до этого, тоже не
  будут работать — соберите заново).
- **Ошибка при входе по email/паролю** → приложение покажет текст ошибки от
  Firebase как есть (например, «пароль слишком короткий» — минимум 6 символов,
  или «такой аккаунт уже существует» — тогда нужно «Войти», а не
  «Зарегистрироваться»).
- **Вход проходит, но данные не появляются** → проверьте, что
  `GOOGLE_SERVICES_JSON` в секретах — это именно содержимое файла, а не
  путь к нему, и что JSON не обрезан при копировании.
- **Хочу проверить, что данные реально пишутся** → Firebase Console →
  Firestore Database → Data — там будет видно дерево
  `users/{ваш uid}/habits/...` и `.../logs/...` в реальном времени.
