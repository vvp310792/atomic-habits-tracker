# Atomic Habits Tracker — контекст проекта

Этот файл — сжатая память всего, что было решено и построено в проекте до
сих пор. Он написан для того, чтобы новая сессия (в том числе в Claude Code)
не начинала с нуля и не переоткрывала уже принятые решения заново.

Приложение — не реализация одной методологии, а **синтез нескольких**:
Джеймс Клир (Atomic Habits) даёт каркас (Scorecard, 4 закона, идентичность,
стек), но поверх встроены отдельные, самостоятельные механики из других
источников — см. раздел «Источники методологии» ниже. Если в разговоре
всплывает идея из ещё одной книги — по умолчанию она НЕ дублирует то, что
уже есть, а добавляет отдельную ось (см. пример с Ленгольд ниже).

## Стек и структура

Kotlin + Jetpack Compose (Material3), Room (единственный источник правды для
UI, offline-first), Firebase Firestore (синхронизация поверх Room, не вместо
неё), Firebase Auth (Google Sign-In). Без ViewModel — Compose-локальное
состояние (`collectAsState`/`remember`/`LaunchedEffect`) напрямую поверх
Flow из репозиториев. Осознанное упрощение под масштаб одного разработчика.

```
data/          Entity + Dao + Repository — вся бизнес-логика и SQL
ui/<screen>/   один пакет на экран
ui/components/ переиспользуемые composable
sync/          FirestoreSyncManager, AuthManager
notifications/ ReminderScheduler/Receiver, AlarmManager
export/        DataExporter — JSON-экспорт для анализа (в том числе мной)
util/          чистые функции без побочных эффектов
navigation/    Routes + NavHost + нижнее меню
```

Текущая версия БД — **v19**. Каждая миграция аддитивна, ничего не удаляется
деструктивно (см. «Грабли» ниже).

## Модель данных — что есть и зачем

### `Habit` — универсальная сущность (одна и та же для полезных/вредных/справочных)
Ключевые поля и что они значат:
- `qualityType` (USEFUL/HARMFUL/NEUTRAL/DESIRED) — честная категория из
  Scorecard, что это ЗА привычка, независимо от того, отслеживается ли она
- `isTracked` — отслеживается ли активно (чекбокс на «Сегодня», логи,
  напоминания) или просто существует как справочная запись (якорь цепочки,
  цель на будущее). Оси `qualityType` и `isTracked` независимы
- `activeDays` — битовая маска дней недели (бит0=Пн...бит6=Вс), 127=каждый день
- `stackAnchorId`/`stackAnchorLabel` — habit stacking (Клир): «После X я
  сделаю Y». Один якорь — один ребёнок (без ветвления, проверяется в
  редакторе привычки — уже занятые якоря исключаются из списка кандидатов)
- `identityId`/`identityLabel` — привязка к идентичности (Клир): каждое
  выполнение — голос за идентичность
- `temptationBundle` — temptation bundling (Кэти Милкман): что разрешено
  ТОЛЬКО во время этой привычки. Отдельное от `stackAnchorId` — bundling про
  одновременность и приманку, stacking про последовательность и порядок
- `difficultyNote`/`difficultyBumpedAtEpochDay` — Goldilocks Rule: текстовое
  описание текущей сложности + дата последнего «усложнения». Бамп сбрасывает
  часы автоматизма (см. `computeMastery` ниже) — усложнённая версия честно
  должна заново заслужить статус «освоено»
- `manuallyMastered` — ручной статус «уже освоено де-факто» (для привычек,
  автоматичных годами ещё до приложения) — независимо от отслеживания и без
  накопления данных. Голосов за идентичность при этом не начисляется —
  отслеживания-то нет
- `selfBindingAction` — self-binding (Анна Лембке): что делаю ЗАРАНЕЕ, чтобы
  физически убрать доступ к вредной привычке (для HARMFUL)
- `journalCycleStartEpochDay` — начало текущего 30-дневного цикла дневника
  (см. `HabitJournalEntry` ниже), 0 = цикл не начат

### `HabitLog` — факт выполнения на конкретный день (`habitId` + `dateEpochDay`)

### `Identity` — идентичность по Клиру (`statement`, `archived`)

### `HabitJournalEntry` — дневник вредных привычек (метод Мисудзу Накасимы, CBT)
**Полностью заменил** старый экран «Позыв» (check/cross, квадратное дыхание —
оба убраны из приложения целиком). Модель — не бинарная, а по 4 колонкам из
книги: `todaysEvents`+`hadIncident` (контекст дня), `hadSlip` (⚠️ **явный
чекбокс — источник правды**, НЕ парсинг текста в `amount`; была реальная
ошибка, когда подсказка советовала печатать «0», а непустая строка "0"
засчитывалась как срыв — см. «Грабли»), `amount` (описательный текст, только
если `hadSlip=true`), `whatIWanted` (переосмысляется каждый день заново, а не
фиксируется один раз), `substituteBehavior`+`substituteSucceeded`.
`cycleStartEpochDay` — какому 30-дневному циклу принадлежит запись.

### `PausePeriod` — пауза (командировки)
Диапазон дат + `pausedHabitSyncIds` (список через запятую, **опт-ин по
конкретной поездке**, не глобальный тумблер — в одну командировку продолжаешь
аудиокниги, останавливаешь тренировки, в другую может быть наоборот).
Приостановленный день исключается из подсчёта стрика/процента/освоения
ТОЧНО ТАК ЖЕ, как нерабочий день недели — не считается ни выполнением, ни
пропуском. Если всё-таки сделал во время паузы — засчитывается как обычная
победа (пауза прощает пропуски, не отменяет попадания).

### `ImpulseLog` — legacy-таблица
Старая модель check/cross до перехода на дневник Накасимы. **Не используется
в текущем UI**, оставлена только как исторические данные (не удалена
деструктивно — см. «Грабли»). Не путать с `HabitJournalEntry`.

## Ключевые механики — как что считается

### Освоение привычки (mastery)
`HabitRepository.computeMastery()`. Окно — **90 ЗАПЛАНИРОВАННЫХ дней**, не
календарных: для привычки «только будни» окно растягивается по календарю
назад (условно ~126 календарных дней), пока не наберётся 90 реальных
запланированных случаев — иначе будничная привычка получала бы заниженную,
несправедливо лёгкую цель по сравнению с ежедневной за тот же календарный
срок.

**Порог освоения — `MASTERY_MIN_SCHEDULED_DAYS = 90` (не 14!).** «80% из 90»
должно буквально означать 72 реальных выполнения из 90 реальных
запланированных дней — не 80% от маленькой ранней выборки, которая просто
случайно проходит по проценту. Это было реальной багой: привычка с 25
идеальными днями подряд помечалась «Освоено» преждевременно, пока порог не
подняли до полных 90.

Отдельная, гораздо более низкая планка `MASTERY_MIN_DISPLAY_DAYS = 14` — ТОЛЬКО
для того, показывать ли вообще какой-то процент в UI (иначе 3-дневная
привычка увидела бы пустоту вместо честного «7% к автоматизму»). Обе
константы — в `HabitRepository.kt`, единый источник правды, UI не хардкодит
числа повторно.

`MasteryInfo.progressPercent` — не сырой процент выполнения, а
«сколько из необходимых 72 выполнений уже накоплено» (`done / target * 100`,
где `target = 90% × 80%`), капается на 99% пока реально не освоено — освоено
даёт ровный 100% независимо от того, сколько из 90 дней прошло (простая
привычка по Lally может освоиться и за 18 дней).

Пауза (`PausePeriod`) и Goldilocks-бамп (`difficultyBumpedAtEpochDay`) оба
влияют на этот расчёт — паузные дни пропускаются как нерабочие, бамп
двигает точку отсчёта окна вперёд (сбрасывает прогресс для новой, более
сложной версии).

### Стрик и процент выполнения (30 дней)
`HabitRepository.computeStats()`. Использует ту же схему учёта
запланированных/паузных дней, что и mastery — единая функция `isActiveOn(habit,
date, pausePeriods)` внутри файла.

### «Дней без» для вредных привычек
`computeJournalDaysWithout()` в `HabitJournalRepository.kt` — считает по
`hadSlip` (явный флаг), НЕ по пустоте `amount`. Framing нарочно спокойный
(щит 🛡, не огонь/стрик) и без «ты всё сломал» при свежем срыве — согласуется
с изначальным принципом ImpulseLog: один срыв не должен ощущаться как
«весь день/забег испорчен» (эффект «какого чёрта», what-the-hell effect).

### Напоминания
`ReminderScheduler`/`ReminderReceiver`. Будильник ставится на ближайший
реально запланированный день (`activeDays`-aware, а не наивно «завтра»).
Перед показом уведомления — тройная проверка: сегодня запланировано ИЛИ нет,
не на паузе ли привычка сейчас, и **не отмечена ли уже выполненной сегодня**
(последнее — по модели B=MAP Фогга: уведомление про уже сделанное — не
триггер, а шум, который топит реально нужные напоминания).

## Экраны и навигация

Нижнее меню: **Сегодня** / **Привычки** / **Дневник** / **История** / **Я**.

- **Сегодня** — разделено на два явных поля: «✅ Сделал» (отслеживаемые
  полезные/нейтральные/desired, обычный чекбокс) и «🛡 Устоял» (отслеживаемые
  вредные, статус на сегодня + «дней без», тап открывает Дневник с
  предвыбранной привычкой через `savedStateHandle`, не через route-параметр)
- **Привычки** — полный список, цепочки (стек), drag-and-drop между
  временем суток, бейджи освоения/паузы/temptation bundle
- **Дневник** — заменил «Позыв», см. `HabitJournalEntry` выше
- **История** — календарь месяца (недели строками вниз, Пн-Вс шапка),
  диаграмма дневника за 30 дней (по `hadSlip`, не по логам событий),
  достижения
- **Я** — Scorecard, идентичности (с переименованием, каскадно обновляющим
  `identityLabel` у привязанных привычек), экспорт данных (JSON), паузы
  (командировки), обновления приложения

## Грабли — реальные баги, на которых спотыкались

- **`key()` обязателен при live-реордере в drag-and-drop.** Без явного ключа
  Compose сопоставляет composable по позиции, а не identity элемента — при
  живом перетаскивании это рвёт активный жест на середине (реордер визуально
  срабатывает, но сохраняется неверно)
- **`rememberCoroutineScope()` отменяется при уходе с экрана.** Для операций,
  которые ОБЯЗАНЫ дописаться (сохранение, реордер, отметка выполнения) —
  собственный `appScope` уровня `Application` (`HabitTrackerApp.launchPersistent`),
  не экрана
- **Route с query-параметром ломает подсветку таба нижнего меню**, если этот
  экран есть в BOTTOM_TABS (`destination.route` перестаёт совпадать с
  шаблоном таба). Передавать данные между экранами через
  `savedStateHandle.set()`/`.remove()` (одноразовое потребление), не через URL
- **`Modifier.padding()` не смешивает `horizontal` с `top`/`bottom`
  по отдельности** — либо все четыре стороны, либо `horizontal`/`vertical` парой
- **Дни недели — считать по «запланированным», не по календарным.**
  Будничная привычка не должна засчитывать выходные как пропуски —
  `isActiveOn` пропускает нерабочие дни полностью, не штрафует
- **Не парсить текстовое поле как источник булевого факта.** Была ошибка
  ровно в этом: подсказка советовала печатать «0» для «чисто», но непустая
  строка "0" читалась кодом как «есть срыв». Для любого да/нет-факта — явный
  чекбокс, не эвристика по содержимому текста
- **Debug-keystore коммитить в репозиторий, фиксированный** — иначе каждая
  пересборка CI получает новый случайный ключ и Google Sign-In (привязанный
  к SHA-1) ломается
- **Room-миграции только аддитивные.** Никогда `fallbackToDestructiveMigration`,
  никогда не удалять старые таблицы физически (см. `impulse_logs` — оставлена
  неиспользуемой, не удалена)
- **Логи сборки GitHub Actions недоступны напрямую агенту** (Azure blob
  storage не в разрешённом списке доменов) — единственный надёжный способ
  получить точный текст ошибки компиляции при упавшей сборке: попросить
  пользователя скачать `.zip` с логами вручную из вкладки Actions и прислать

## Бэклог — обсуждали, но НЕ реализовали

Из разных обсуждений за всё время работы над проектом, ничего из этого не в коде:

- **«Никогда не пропускай дважды»** — есть научное обоснование в
  разговорах, нет самого детектора/подсветки в UI (инфраструктура готова —
  `isActiveOn` уже умеет отличать реальный пропуск от незапланированного дня)
- **Правило 2 минут как отдельная логируемая механика**, не просто текстовое
  поле `lawEasy`
- **Celebration/«Shine» при отметке выполнения** (Фогг) — короткая
  эмоциональная реакция сразу после чекбокса (анимация/фраза), центральная
  идея книги, максимально дешёвая в реализации, ничем не покрыта
- **B=MAP-диагностика буксующей привычки** — если стрик рвётся раз за разом,
  явно спросить «чего не хватает: мотивации, простоты действия или
  триггера», вместо молчаливой статистики
- **Golden Behaviors / Focus Mapping** (Фогг) — упражнение выбора «золотых»
  поведений при заведении новой привычки
- **Тестирование нескольких «рецептов» привычки** до фиксации на одном (Фогг)
- **Тег Фундамент/Драйв/Кайф** (Катерина Ленгольд, Нейроспринт) —
  ОРТОГОНАЛЬНАЯ ось к существующим 7 сферам жизни: не «где» (карьера/здоровье),
  а «как это действует на нервную систему» (достижение vs чистое удовольствие
  без цели). Плюс недельная визуализация баланса
- **Интеграционные недели** (Ленгольд) — каждые ~3 недели мягкое
  напоминание не добавлять новых привычек, свериться с уже идущими
- **WOOP / obstacle plan** (Эттинген) — поле «что вероятнее всего помешает +
  план если-то», симметрично уже существующему `alternativeSuggestion`
- **Поле «трение среды»** (Клир, закон 1 инверсия) — насколько физически
  неудобно начать/остановить привычку
- **Осознанность повторения** (Дойдж, миелин) — необязательный тумблер «было
  осознанно или на автомате» при отметке
- **Active recall** (Питер Браун) — для интеллектуальных привычек, «что
  запомнил?» вместо пассивной галочки
- **Интенсивность тренировки** (Джон Рэйти, BDNF) — пульс 120+ да/нет для
  HEALTH-привычек
- **Минуты медитации накопительно** (Гоулман/Дэвидсон) — не только дни, но
  и сумма минут практики с милстоунами
- **Физиологический чек-ин** (Макгонигал) — сон/стресс/голод + корреляция с
  процентом выполнения
- **Precommitment/ставки** за срыв — частично покрыто self-binding, но не
  как явный денежный/социальный commitment-механизм
- **Количественные привычки** (не да/нет, а число) — конкретный юзкейс
  Deep Work (Ньюпорт): минуты непрерывного фокуса
- **Виджет на главный экран**, синхронизация с Google Fit, гео-напоминания,
  Wear OS — из сравнения с конкурентами, ничего не начато
- **CSV/PDF-экспорт** — сейчас только JSON
- **Визуальное отделение освоенных привычек** от ещё формирующихся (сейчас
  только бейдж «Освоено», нет отдельного списка/фильтра «на автопилоте»)
- **Предиктивные пре-напоминания** (Лиза Фельдман Барретт) — самая
  необязательная идея из всего списка, можно пропустить без потери целостности
